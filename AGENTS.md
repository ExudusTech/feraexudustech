# Architecture rules
- Subdirectories have their own AGENTS.md (e.g. supabase/functions/mcp); read it before changing files there.
- Validate visit windows before writes; rejected bookings have no operational side effects.
- Resolve chat participants as tenant-scoped people and reuse only an open lead for the same person and establishment, so one person can represent multiple companies without cross-linking opportunities.
- Load shared and tenant holidays through one calendar helper before visit writes, and filter route candidates within the bounded lookahead so municipal exclusions stay city-specific; shared calendar edits require super-admin authority to prevent cross-tenant changes.
- Capture booking email with a tenant-scoped conditional update after successful schedule creation so existing contact email is never overwritten.
- Team notifications use organization/event subscriptions and guarded EdgeRuntime background delivery; failures never change MCP responses, provider bodies are never logged, and demo records (_shared/demo-guard.ts) never send.
- Notification links open only records returned under existing access policies, carry a validated same-origin destination through login and organization selection, and wait for profile hydration and successful organization switching; this prevents lost destinations and stale-tenant reads.
- Schedules persist their origin and inherit the selected coverage area's optional tenant-validated consultant at creation; manager-wide Agenda views remain explicitly scoped to the selected organization so unassigned Flora visits are visible without cross-tenant leakage.
- Flora booking/handoff validate company/person first; product priority: params → same-company lead → successful 24h chat lookup; location stays company-matched.
- Users are created only server-side (create-user sets organization and role); the signup trigger grants just 'visitante' and never reads user metadata, so self-signup cannot join a tenant or escalate.
- Owner-or-privileged UPDATE policies plus an immutability trigger on organization_id/created_by protect leads, clients and schedules; service-role paths (mcp) bypass both.
- Flora leads and visits fall back to the organization's flora_default_lead_owner (coverage consultant first for visits); bulk reassignment runs in a security-definer function that backs up rows first.
- Users may hold several roles; the app merges permissions as the union (src/lib/permissions.ts) and role changes go only through create-user/manage-user (shared rules in supabase/functions/_shared/roles.ts), so admin limits stay enforced server-side.
- Role edits check backups before writes, add idempotently before removing old roles, and verify the saved set; failures expose only allowlisted messages and log stage/code without personal data.
- Organization branding is applied at runtime from the organizations row (colors via injected CSS vars with WCAG-checked foregrounds, logo, favicon, manifest); legacy default colors count as "not customized" so other tenants keep the Exudus brand.
- Organization logos live in the private org-logos bucket (public buckets are blocked in this workspace) and are referenced by long-lived signed URLs in organizations.logo_url.
- Notification recipients reference org users by user_id and read WhatsApp live from profiles.phone (external contacts keep their own number); a trigger blocks duplicate users/numbers so one person is never alerted twice.
- Loan equipment is manufacturer-neutral: comodatos and maintenance_schedule (work orders) carry a fabricante field; legacy ekkoa_* tables are DEPRECATED except ekkoa_coverage_areas (used by Flora), and /ekkoa only redirects.
- Per-role read-only screens use readOnlyRoutes in src/lib/permissions.ts (read-only only if every granting role says so), and denied routes redirect to the first allowed home screen.
- Visit alerts split into commercial/technical events; Flora notifies from mcp, Fera visits via notify-schedule (caller's access, notification_logs dedupe), keeping tenants isolated with no new secret.
- Sync products.disponibilidade/is_active; MCP category ranks or suggests, never filters term matches.
- Product images: storage paths in private product-images, signed 1h only at display/send so nothing expires; Flora sends ≤1 image per chat/product/24h (product_image_sends), only if pode_enviar_foto_cliente.
- Human-service hours live in supabase/functions/_shared/business-hours.ts; mcp embeds an identical copy (test-enforced) because its test harness cannot load imports, so Flora, the queue and screens agree.
- Team alerts outside human hours are stored as QUEUED notification_logs and released by release-notification-queue (5-min cron), which also sends atendimento wait reminders; bookings still alert immediately.
- Atendimentos (one open per lead) are created by mcp; Fera actions go through atendimento-acoes, which reads the row with caller RLS before using the GPT Maker token or writing the timeline.
- The Leads kanban is built from lead_stages via stage_id; a BEFORE trigger on leads (sync_lead_stage) keeps the legacy stage enum in sync in both directions so older readers keep working.
- Funnel timing uses only trigger-written history and first-time milestones (no backfill), never updated_at; math and the manager-only gate live in _shared/funil-tempos.ts (identical mcp copy, test-enforced).
- No parallel structures: points are comodatos, visits are schedules with check-in/schedule_evidencias (estado = point checklist), replacement tasks and urgent requests are maintenance_schedule work orders (tipo_os substituicao, aprovacao_status); client_visits, ekkoa_* (except coverage) and the Lote 11 side tables are DEPRECATED. Field writes go through base-instalada after a caller-RLS read.
- Company contacts are pessoas linked through empresa_contatos (lead or client, one primary mirrored to leads.pessoa_id/contact_*); client_contacts is DEPRECATED, so one person can represent many companies without duplicate person rows.
- Leads become clients only via converter_lead_em_cliente (dedupe CNPJ > place_id > name+city, copies contacts, idempotent); direct client inserts are privileged or origem base_existente, so prospects never bypass the lead pipeline.
- Same-user auth events (token refresh, focus SIGNED_IN) never show the global loader or downgrade a loaded user, and visit forms keep local drafts (src/lib/visit-draft.ts); the phone camera once unmounted visits and lost data.
- Check-in geolocation uses the typed capture helper with memory-only recent-position fallback; the server validates diagnostics and marks sem_permissao only for explicit denial, because missing GPS does not establish permission state.
- Refill compatibility is resolved by refisCompativeis: refill specifications naming the dispenser, then products.compatible_dispenser_families ∋ dispenser_family_id, then same brand with "ver todos"; no new table.
- Revisits: one visit per client, device-driven, only via _shared/revisita*.ts; new points are saved evaluated, so closing never waits on hidden steps.
- Check-in destination is schedule → client → lead coordinates, geocoded on demand and by the 15-min scheduler (geocode_tentado_em stops repeat lookups); a missing destination is flagged destino_sem_coordenadas, never treated as inside the radius, and a check-in position becomes the address only after the consultant confirms.
- Occurrences are schedules (OC number, type, coleta_*); audio/text notes are schedule_evidencias; planned points are comodatos PREVISTO; only coleta-ocorrencia processes drafts.
- Recurrence uses route days unless the plan's modo_agenda is 'data'; unattached required invoices block check-in server-side unless a manager release is recorded.
- Mobile (390px) never scrolls sideways: lists use .table-cards (index.css; data-card/data-label cells), dialogs render full-screen, side-by-side fields stack; below md a bottom nav replaces the side menu, installability is manifest-only.
- EM_TESTE devices change status only when their billing tasks (comodato_ids) conclude, so stock follows invoices.
